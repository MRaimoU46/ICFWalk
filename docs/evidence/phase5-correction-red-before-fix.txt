ICFWalk Phase 5 correction -- red-before-green evidence
=======================================================

Each new regression was run against the Phase 5 implementation exactly as committed at 2522e79,
with nothing else in the tree changed, and then against the correction. The unfixed file was
restored from `git show 2522e79:<path>` and put back afterwards; no temporary mutation remains in
the tree (see the final `git status` at the end of this file).

Two defects have executable red-before-green evidence here. The third (the summary concurrency
regression itself) requires SQL Server, which this environment could not provide; what was and was
not established for it is recorded at the end.

The four failures, verbatim, each naming the audited behavior:

      1 !== 2

      One PUT, not two. The edit made during the in-flight save was still on the autosave timer
      when the export ran; the export saw app.dirty, built a Blob, and never sent it.

  [2] a definitive 4xx save rejection produces no download and an accurate message
      AssertionError [ERR_ASSERTION]: no file may be downloaded, but one arrived from
      blob:http://127.0.0.1:37995/ee6ef035-ad3b-45b6-81e1-d41b8c4a5be6

      +   text: 'ICFWALK SUMMARY\n================\nGrade level: 2\nDate: 2026-09-20\n\n'
      +         'PART 3 - CONDITIONS FOR LEARNING\nNotes: an edit the server will refuse',
      +   url: 'blob:http://127.0.0.1:37995/ee6ef035-ad3b-45b6-81e1-d41b8c4a5be6' }
      - null

      The server was reached and refused the state; the browser produced a file containing the
      refused state anyway.

  [3] an HTTP 5xx blocks the export as an unfinished save, not as a network failure
      AssertionError [ERR_ASSERTION]: no file may be downloaded, but one arrived from
      blob:http://127.0.0.1:37995/8f6e1688-2d50-47e3-85c5-a4709f3d53b3

      AssertionError [ERR_ASSERTION]: and that the browser made it
      actual: 'The server could not be reached, so the exported summary was built from what is on
               this page.'
      expected: /generated in your browser/i, operator: 'match'

      The one case the fallback is for still worked, but the message did not say the file was
      generated in the browser from unsaved information.

The three that passed under the unfixed code are there on purpose: a conflict already blocked the

2. DEFECT 1 -- summary materialization under the walk mutation lock
-------------------------------------------------------------------------------------------------

tests/cfml/specs/WalkSummaryCoherenceTest.cfc carries three cases. One of them,
testEveryMutationPathTakesTheSameWalkLock, reads the repository source through BaseSpec.repoFile
and touches no database, so it was run here on Lucee 6.2.8.20 with no SQL Server present.

RED: src/walks/WalkService.cfc replaced with the 2522e79 version.

  {
    "status": "FAILED",
    "test": "testEveryMutationPathTakesTheSameWalkLock",
    "type": "ICFWalk.Test.AssertionFailed",
    "message": "the summary export is materialized inside a transaction Expected to find
                [variables.db.transact(function() {] in [public struct function summary(required
                struct principal, required string walkId) {\n\t\tvar access =
                variables.authz.authorizeWalk(arguments.principal, arguments.walkId, \"read\");
                \n\t\tvar row = variables.walks.findWalk(access.walkId);\n\t\tif
                (structIsEmpty(row)) variables.errors.notFound();\n\t\tvar dims = va]."
  }

GREEN: correction restored, same page, same engine.

  { "status": "PASSED", "test": "testEveryMutationPathTakesTheSameWalkLock" }

NOT RUN HERE: testASummaryExportCannotStraddleAConcurrentSave and
testTheLockedExportStillWritesNothingAboutTheWalk. Both drive the real service against a real
database and both need SQL Server's UPDLOCK/ROWLOCK semantics, which is the entire point of the
regression -- no substitute engine would prove anything about it. SQL Server could not be installed
in this environment; see docs/evidence/phase5-correction-environment.md. The spec compiles on
Lucee 6.2.8.20 (all 67 repository components compile, 0 failures) and its structural case runs
green, but its concurrency case is UNEXECUTED and the audit should treat it as such.
