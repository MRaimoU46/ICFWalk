3. A8-01 readiness correction
Result: VERIFIED AND CLOSED
The old health decision was:
database == "ok" && longText != "truncated"
The corrected decision is:
database == "ok" && schema == "present" && longText == "ok"
This is the required fail-closed readiness contract. A reachable database without the ICFWalk schema now produces HTTP 503 with status: degraded; a node is ready only when the database responds, the schema is present, and the long-text probe is intact.
Evidence independently inspected:

- The live operation uses a newly created, reachable SQL Server database with zero ICFWalk tables. On both engines it records 503 before migrations, 200 immediately after migrations without an application restart, and 200 after restart.
- The same live operation run against the audited old code fails on both engines because the old endpoint answers 200 before the schema exists.
- Production responses are checked for the safe, reduced response shape and correlation-id behavior.
- Operations and endpoint documentation now agree with the code.
The raw operation TAP files record 1 of 1 passing on the corrected code for each engine. Each old-code live-red TAP records the intended 0 of 1 result, with the specific HTTP 200 versus 503 failure. This is a proper red-before-green chain.
4. A8-03 report failure correction
Result: VERIFIED AND CLOSED IN THE ORIGINAL SCOPE
The correction identifies the previously unexplained Lucee 500 responses as SQL Server deadlock-victim failures in live district reports and their CSV form. The implementation now catches native error 1205 or SQLSTATE 40001, discards the rolled-back attempt, logs a bounded diagnostic event, and recomputes within the existing maximum of three attempts. A non-deadlock error or a deadlock on the third attempt is rethrown. The existing REPORT_POPULATION_CHANGED semantics are not misused.
The new regression test forms a real SQL Server deadlock rather than imitating an exception. It gives the competing session higher deadlock priority, proves that the report transaction receives error 1205, verifies that the first victimized attempt is retried successfully, and verifies that three consecutive victimizations still fail as a database error instead of returning a false population-change response. The submitted targeted records pass on both engines together with the pre-existing report specifications.
The raw workload records support the diagnosis and correction:
- Three pre-correction full-population Lucee drafts-only attempts contain 7 unexpected failures in total, all in the second attempt.
- All 7 are HTTP 500 INTERNAL_ERROR responses from live or CSV district reports at the 25-user level.
- All 7 carry a matching request.failed event with a SQL Server deadlock-victim message and a matching SQL Server deadlock graph.
- Eight correction-commit workload runs, five Lucee drafts-only, one Lucee mixed-population, one ColdFusion drafts-only, and one ColdFusion mixed-population, contain zero unexpected responses.
- Twelve deadlocks in the corrected Lucee runs are matched to twelve report.deadlock.victim events across ten requests. Seven requests succeed and three finish with the already-expected 409 population-change refusal. None returns an unexpected error.
- The two mixed-population runs retain 26 expected 409 responses on Lucee and 40 on ColdFusion. These are separated from unexpected failures and are not represented as successes.
The correction therefore explains the original symptom, provides correlation evidence, reproduces the cause, adds a deterministic regression, and demonstrates the retry under workload.
Residuals remain documented and are not new freeze blockers for this low-severity finding:
- Deadlocks still occur and can consume one or more retry attempts.
- Three consecutive deadlock-victim outcomes still return a database error.
- Release creation uses a related read path and does not receive this retry; no such failure was observed.
- Eliminating the underlying lock conflict would require an owner decision and a database isolation change.
- The separate Phase 8 performance target remains open.
