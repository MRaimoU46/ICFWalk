# Phase 8 defects

Every defect below was reproduced by a failing regression before it was corrected, corrected with
the smallest change that made the regression pass, and then covered by the full gate on the Phase 8
code commit. Severity is the impact on the target platform (Adobe ColdFusion 2023 + SQL Server)
if it had shipped. Transcripts are in `defects/`.

| ID | Severity | What was wrong | Correction | Regression (red, then green) | Engines |
| --- | --- | --- | --- | --- | --- |
| P8-01 | HIGH | The page read its CSRF token once. After an application restart or an idle session timeout the identity adapter starts a new session with a new token, so every save, create, completion, import and release was refused 403 `CSRF_TOKEN_INVALID`, Retry could never succeed, and a reload discarded the unsent edits. | `api.js` renews the token from `/api/me` and sends the refused request once more, unchanged, only while the session belongs to the same person (otherwise `SESSION_USER_CHANGED`, nothing sent). The router refuses a token before reading the body, so the refused request changed nothing. | `tests/node/browser-session-recovery.test.mjs` (`P8-01-red.txt`, `P8-01-green-targeted.txt`) | both |
| P8-02 | CRITICAL | The frozen code did not start on Adobe ColdFusion 2023: `cfcompile` refused eight application templates and three specs (reserved words as variable names, arguments re-declared with `var`, unscoped calls to names ColdFusion resolves to its own page methods, `c ? ["A"] : []`), and at run time DML returned nothing from `Db.run`, `isNull(arr[i])` threw, non-ASCII literals were read in the JVM's default charset, and arrays were passed to functions by value (the snapshot's sort did not stick and its checksum differed). | Minimal renames and rewrites, `this.passArrayByReference = true`, an empty query from `Db.run`, `arrayIsDefined`, `chr()` for non-ASCII text. | `tests/node/cfml-portability.test.mjs` rules 1 to 6, and the CFML suite on ColdFusion (`P8-02-red-*.txt`) | ColdFusion |

| P8-04 | CRITICAL (default ColdFusion datasource) | Without "Enable long text retrieval (CLOB)" ColdFusion returns the first 32,000 characters of an `nvarchar(max)` value. The instrument snapshot is about 218,000, so nothing could render or save; replay records and revision snapshots can exceed it too. | The application-defined ColdFusion datasource sets `disable_clob` false, `tools/runtime/acf-up.sh` does the same for the administrator datasource, and `/api/health` reports `checks.longText` and answers 503 when long text is truncated. | `LongTextRetrievalTest` with `TruncatingDb` (`P8-04-red-acf.txt`, `P8-04-green-acf.txt`) | ColdFusion |
| P8-05 | MEDIUM | Session identifier cookies were persistent: Lucee sent CFID with a 30-year `Expires`, ColdFusion sent CFID and CFTOKEN with `Max-Age=946080000`. | P8-06 | MEDIUM (mitigated by the CSP) | An imported item's `linkUrl` accepted any scheme and was rendered as a live link, so a `javascript:` or `data:` address in an instrument document became a clickable link in the editor. The strict Content-Security-Policy already blocked script execution. | `DefinitionValidator` refuses anything but an absolute `http://` or `https://` address (`INVALID_LINK_URL`); the renderer links nothing else and shows the help text as text. | `LinkUrlSchemeTest`, `browser-xss-sweep.test.mjs` "P8-06" (`P8-06-red-*.txt/tap`, `P8-06-green-*.txt/tap`) | both |
| P8-07 | LOW (tests only) | The test harness assumed Lucee: suite parts too large for ColdFusion's speed, SQL error text read from `message` only, structure comparisons sensitive to ColdFusion's number formatting, CFML boolean literals, and a `cfthread` attribute used to carry a barrier (ColdFusion deep-copies thread attributes, so one export spec failed there and three "did not finish while held" checks could never observe anything). | `ICFWALK_CFML_SUITE_PARTS`; `BaseSpec.errorText`; canonical-JSON comparison; threads reach a spec's barrier through its `variables` scope, with an added assertion that the completion signal arrives; portability lint rule 8. Three P6A-01 cases declared a 50 MB body, above ColdFusion's own 20 MB post ceiling, where ColdFusion answers before any CFML: they declare 15 MB (still three times the import limit, never sent) and a new case records each engine's answer above the ceiling. The keyboard sweep's fixed 600-press ceiling follows the control count (699 controls on a long-lived admin list). No assertion was weakened. | The ColdFusion discovery runs; `P8-07-thread-barrier-red.txt`, `P8-07-thread-barrier-green.txt`, `P8-07-thread-barrier-diag.txt`; `../acf/run-3/acf-node-run3.tap` (the post-ceiling, admin and traversal cases) | ColdFusion |
| P8-08 | HIGH (ColdFusion) | ColdFusion 2023's `isNull()` is true for any string whose value is "null" in any letter case. Every guard written with it took a person named Null, a note reading "null" or an org unit called NULL for a missing value. | `isNull()` replaced by `structKeyExists()` / `arrayIsDefined()` across `src/` (query cells, where the quirk cannot reach, keep it); portability lint rule 7. | `NullTextTest`, `tests/node/null-text.test.mjs` (`P8-08-red-8500.tap` red on ColdFusion, green on both after) | ColdFusion |
| P8-09 | LOW | `JsonTypes.isJsonBoolean` recognised `java.lang.Boolean` only; ColdFusion's CFML boolean literals are `coldfusion.runtime.CFBoolean`, so a metadata patch built in CFML was refused as "not a boolean" there. | Both classes are booleans. | `EngineBooleanTest`; red in the first ColdFusion discovery run (`../acf/discovery-1/part-2-of-12.json`, `part-6-of-12.json`: 28 failures), green after | ColdFusion |
| P8-10 | MEDIUM (ColdFusion) | ColdFusion's `arrayContains()` compares numeric-looking strings as numbers, so the option filter kept grade "9.0" among the options "9", "10", "11", "12" where the shared vectors, Lucee and the browser clear it. | `VisibilityEngine` compares codes as exact text. | `VisibilityEngineTest.testMatchesTheSharedVectorsExactly`: red on ColdFusion in `../acf/discovery-2/part-8-of-12.json`, green after (`acf-targeted-green.txt`, and the final gate) | ColdFusion |
| P8-11 | MEDIUM (performance) | My Walks read the dimension values of every walk its WHERE clause matched, not of the 500 it kept: a district walker's "all walks in my scope" moved about 200,000 rows to show 500, taking 1.6 to 3.6 seconds on 30,000 walks and growing with every walk ever made. | The dimension read is limited to the listed walks' ids. | `WalkListBoundTest` with `RecordingDb` (`P8-11-red-*`, `P8-11-green-*`: p50 1,607 ms / 208,205 rows before, 917 ms / 3,796 rows after) | both |
| P8-12 | MEDIUM (clean install) | The documented bootstrap (`docs/OPERATIONS.md` 4.6, `docs/LOCAL_SETUP.md` 6 to 9) mapped every SCHOOL unit to its School value before any version was published, and asked to publish before the administrator existed. Production serves no DRAFT, so the mapping was refused 400 `INSTRUMENT_NOT_AVAILABLE` and a clean production install could not follow its own steps (SEC-07). | Both procedures reordered: seed, org units without mappings, people, the first publication, then the mappings, then maintenance off. No code changed: validating a mapping against the version in service is deliberate. | `tests/ops/production-profile.test.mjs` (`P8-12-red-lucee.tap` on the documented order, `P8-12-green-lucee.tap` on the corrected one) | both |
| P8-13 | LOW (usability; visible on ColdFusion) | After a change, the administration page showed its success message ("Saved 1 change to ...", "Published ...", "Discarded draft ...", "Created draft ...", "Re-imported draft ...") before refreshing its version list, while it still ignored clicks. A person who acted on the message clicked into a busy page and nothing happened. Where the list answers in milliseconds the window is invisible; on ColdFusion it made three browser suites time out. | Each change refreshes the list first and announces its success after, when the page takes the next click. | `browser-admin.test.mjs` "P8-13", with the version list slowed so the window is the same on every engine (`P8-13-red-lucee.tap`, `P8-13-green-lucee.tap`) | both |
| P8-14 | MEDIUM (performance on ColdFusion) | The canonical JSON writer, which every API response, stored JSON document and snapshot checksum goes through, escaped each string one UTF-16 code unit at a time and sorted each struct's keys with a CFML closure, appending through a Java StringBuilder whose overloaded `append` ColdFusion resolves by reflection on every call. A walker's My Walks (81 walks, 72 KB) spent about 400 ms of each request serializing on ColdFusion 2023 and 110 to 290 ms on Lucee, against 2 to 6 ms for the engine's own serializer; under 25 concurrent people that request's median reached 5 seconds on ColdFusion. | Output unchanged: plain strings are appended whole (a precompiled pattern finds anything to escape; the character loop still handles those), keys are sorted by `Collections.sort` (the same `String.compareTo` order), and the parts are collected in an array and joined once. 179 KB: 976 ms to about 90 ms on ColdFusion, about 190 ms to 45 ms on Lucee. | `CanonicalJsonThroughputTest` (red on ColdFusion before, 976 ms against a 250 ms ceiling; green on both after), with `CanonicalJsonTest` and the snapshot checksum specs proving the bytes are unchanged (`P8-14-red.txt`, `P8-14-green.txt`) | both (visible on ColdFusion) |
